Что уже сделано в index.html: форма записи работает, все 5 кнопок её
открывают, поля (имя, фамилия, телефон) собираются. Осталось один раз
сказать сайту, КУДА отправлять собранное. Это делает скрипт Code.gs —
папка booking/ рядом с index.html.


───────────────────────────────────────────────────────────────────────
  ЕСЛИ РЕДАКТОР ПОКАЗЫВАЕТ КРАСНЫЙ КОД
───────────────────────────────────────────────────────────────────────

Красным в Apps Script становится файл, когда одна и та же функция
объявлена в нём дважды. Почти всегда это значит одно: новый код
вставили ПОВЕРХ старого, и старый остался снизу.

Что делать:
  1. Откройте файл Code.gs.
  2. Нажмите Ctrl+A, потом Delete. Файл должен стать пустым.
  3. Вставьте новый код целиком.
  4. Проверьте: в выпадающем списке функций сверху должно быть
     ровно 21 имя, перечисленное в конце Code.gs. Если там больше
     или меньше — код вставился не полностью, повторите с шага 2.

Если красным остаётся отдельная строка, а не весь файл: наведите
на неё курсор, появится подсказка с текстом ошибки. Тот же текст
можно посмотреть в нижней панели «Проблемы».


───────────────────────────────────────────────────────────────────────
  ЕСЛИ У ТЕБЯ УЖЕ ЕСТЬ ТАБЛИЦА СО СТАРОЙ ВЕРСИЕЙ СКРИПТА
───────────────────────────────────────────────────────────────────────

Старая версия писала 7 колонок, новая — 9: добавились «Статус»
и «Согласие», а третья колонка теперь называется «Телефон», а не
«E-mail».

Скрипт это чинит сам: при первой записи он сверяет первую строку
листа с HEADERS и, если она другая, переписывает её. Поэтому
ничего делать не нужно — просто вставьте новый Code.gs и сделайте
новое развёртывание.

Полностью пересоздать листы с нуля (данные пропадут) — rebuildSheets().

Лист «Ошибки» из старой версии больше не используется, его можно
удалить руками: теперь журнал называется «Журнал».


───────────────────────────────────────────────────────────────────────
  ШАГ 1. Создайте таблицу
───────────────────────────────────────────────────────────────────────

  https://sheets.google.com → «Создать» → «Пустая таблица».
  Назовите её, например: «Лаванда — заявки».

  Листы «Заявки» и «Журнал» создавать не нужно — скрипт сделает их сам.


───────────────────────────────────────────────────────────────────────
  ШАГ 2. Откройте редактор скрипта
───────────────────────────────────────────────────────────────────────

  В открытой таблице: меню «Расширения» → «Apps Script».
  Откроется редактор с файлом Code.gs.

  Удалите всё, что там есть, и вставьте содержимое файла
  booking\Code.gs целиком (Ctrl+A, затем Ctrl+V).

  Вставляйте весь файл целиком, вместе с верхним блоком-инструкцией:
  это обычный комментарий, скрипту он не мешает.


───────────────────────────────────────────────────────────────────────
  ШАГ 3. Заполните настройки
───────────────────────────────────────────────────────────────────────

  В начале файла есть блок SETTINGS. Уже заполнено:

    MAIL_TO: 'insigt159@gmail.com'

  Необязательно:

    SHEET_ID        — если вы создали скрипт НЕ из этой таблицы.
                       Возьмите кусок между /d/ и /edit в адресе таблицы.
                       Если скрипт создан из самой таблицы — оставьте ''.

    TELEGRAM_TOKEN  — токен бота от @BotFather.
    TELEGRAM_CHAT   — id чата или группы.

  Токен бота в index.html не вставляйте НИКОГДА — он лежит только здесь,
  на стороне Google. Иначе его увидит любой посетитель сайта.

  DEBUG по умолчанию false — тела запросов с персональными данными
  в «Журнал» не пишутся. Чтобы разобраться, почему заявка не дошла,
  поставьте true на минуту (см. шаг 7) и сразу верните false.


───────────────────────────────────────────────────────────────────────
  ШАГ 4. Проверьте, что скрипт работает
───────────────────────────────────────────────────────────────────────

  Вверху редактора в выпадающей списке выберите функцию setup
  и нажмите «Выполнить» (▶). Google спросит разрешения — согласитесь.

  Должно произойти:
    • появились два листа: «Заявки» и «Журнал»;
    • в «Заявках» строка «Тест / Тестова», в колонке «Согласие» — yes,
      в последней колонке «ок»;
    • на почту пришло письмо «Новая заявка — Лаванда».

  Потом выберите функцию testFromSite и запустите её ещё раз. Это
  главная проверка: она имитирует запрос сайта один в один. Появится
  строка «Анна / Петрова / +7 (999) 123-45-67 / yes / ок». Телефон
  должен быть виден как +7 (999) 123-45-67, а не как #ERROR!.

  ВАЖНО: не нажимайте ▶ при выбранной функции doPost. Apps Script
  вызовет её без аргумента, это не заявка с сайта. Такие вызовы
  теперь пишутся только в «Журнал», в «Заявки» не попадают.

  Если что-то совсем не сработало — внизу редактора есть «Выполнения»,
  там будет видно текст ошибки. Чаще всего это забытый MAIL_TO
  или неверный SHEET_ID.

  Дополнительная проверка, ничего не портит: выберите функцию
  testAllFormats и запустите. Четыре первые строки должны содержать
  «Имя: Анна», остальные — жалобу.


───────────────────────────────────────────────────────────────────────
  ШАГ 5. Опубликуйте скрипт
───────────────────────────────────────────────────────────────────────

  В редакторе: «Развернуть» (Deploy) → «Новое развёртывание».

    Тип:        Веб-приложение
    Описание:   заявки с сайта
    Выполнять:  Я
    Доступ:     Все, у кого есть ссылка     ← важно, иначе сайт не достучится

  Нажмите «Развернуть», при необходимости подтвердите входом в аккаунт.

  Скопируйте URL, который появится. Он заканчивается на /exec:

    https://script.google.com/macros/s/AKfycbXXXXXXXX/exec          ← нужен этот
    https://script.google.com/macros/s/AKfycbXXXXXXXX/dev          ← этот только для теста

  ВАЖНО: при любой правке скрипта после этого нужно создавать НОВОЕ
  развёртывание: «Развернуть» → «Управление развёртываниями» →
  карандаш → «Версия: Новая версия» → «Развернуть».
  Иначе изменения не применятся.


───────────────────────────────────────────────────────────────────────
  ШАГ 6. Впишите адрес в index.html
───────────────────────────────────────────────────────────────────────

  Откройте index.html, найдите три строки в самом конце файла
  (внутри второго <script>, рядом с комментарием «Форма записи»):

    const BOOKING_ENDPOINT = '';
    const BOOKING_CONTENT_TYPE = 'application/json';
    const BOOKING_MODE = 'cors';

  Замените на:

    const BOOKING_ENDPOINT = 'https://script.google.com/macros/s/AKfycbXXXXXXXX/exec';
    const BOOKING_CONTENT_TYPE = 'text/plain';
    const BOOKING_MODE = 'no-cors';

  Все три строки меняются именно так. Apps Script не отдаёт браузеру
  CORS-заголовки, поэтому обычный JSON-запрос блокируется браузером.
  'text/plain' + 'no-cors' — это «простой» запрос, который уходит
  без предварительной проверки. Такой режим уже прописан в коде формы
  и проверен.


───────────────────────────────────────────────────────────────────────
  ШАГ 7. Проверьте с сайта
───────────────────────────────────────────────────────────────────────

  Откройте index.html в браузере, нажмите любую кнопку записи,
  заполните форму — в том числе выдуманный номер — и отправьте.

  Через 10–30 секунд строка должна появиться в листе «Заявки».
  Время появления зависит от Google (иногда до минуты) — это нормально.

  Строка появилась — отлично. Проверьте три вещи:
    • в колонке «Телефон» номер виден как +7 (999) 123-45-67,
      а не как #ERROR!;
    • в колонке «Согласие» стоит yes;
    • в последней колонке «Статус» стоит ок.

  Если строки нет, откройте лист «Журнал». Если заявка не дошла и
  непонятно почему, вернитесь в скрипт, поставьте в SETTINGS
  DEBUG: true, сделайте новое развёртывание (шаг 5) и отправьте
  форму ещё раз. Тогда в «Журнале» появится запись:

    действие:     doPost
    content-type: text/plain
    длина тела:   243
    тело:         {"source":"…","firstName":"Анна",…}

  Если длина стоит 0 — браузер отправил POST без данных, и дело
  в настройках index.html (шаг 6). Если в теле есть ваши имя и
  фамилия, а в таблице всё равно пусто — пришлите этот текст из
  «Журнала», дальше будет понятно, что не так.

  Разобрались — верните DEBUG: false и сделайте новое развёртывание,
  иначе персональные данные продолжат попадать в «Журнал».

  Если строки нет совсем:
    • откройте в браузере адрес развёртывания — должно быть слово
      «Работает». Если страница требует входа — в шаге 5 выбрали
      не «Все, у кого есть ссылка»;
    • откройте index.html через локальный файл (file://) — с сервера
      всё работает так же, но лишних вопросов не будет.


───────────────────────────────────────────────────────────────────────
  ЧТО ПРИХОДИТ В ТАБЛИЦУ
───────────────────────────────────────────────────────────────────────

  Заявки:
    Дата | Имя | Фамилия | Телефон | Согласие | Откуда | Страница |
    Отправлено с сайта | Статус

  «Телефон» — то, что клиент набрал в форме, в том виде, как набрал:
  можно с пробелами, скобками и знаком +. Скрипт пишет номер с
  апострофом на служебном уровне, поэтому он остаётся текстом
  и не превращается в #ERROR!. Дописывать апострофы руками не нужно.

  «Согласие» — «yes», если клиент поставил галочку под текстом
  согласия на обработку персональных данных (152-ФЗ). Галочка в форме
  обязательная, поэтому у любой реальной заявки здесь стоит «yes».
  Вместе с колонками «Дата» и «Страница» это и есть доказательство
  согласия. Пустая ячейка означает, что заявка пришла в обход формы
  (например, через ручной вызов скрипта) — повод разобраться.

  «Откуда» — текст нажатой кнопки: «Записаться», «Забронировать своё
  время» и т.д. Так видно, какая кнопка приносит больше заявок.

  «Страница» — адрес, с которого пришла заявка.

  «Статус» — «ок» если всё разобралось. Если написано
  «НЕ РАСПОЗНАНО: …», значит запрос дошёл с данными, но разобрать
  его не удалось, и дальше стоит причина. Если в таблице вообще нет
  новой строки — запрос дошёл пустым или его не было вовсе; причина
  в «Журнале».


───────────────────────────────────────────────────────────────────────
  КАК ЭТО УСТРОЕНО (если захочется доработать)
───────────────────────────────────────────────────────────────────────

  Форма в index.html шлёт ОДИН POST, тело — одна строка JSON:

    {
      "source":      "Забронировать 90 минут тишины за 2 900 ₽",
      "firstName":   "Анна",
      "lastName":    "Петрова",
      "phone":       "+7 (999) 123-45-67",
      "consent":     "yes",
      "page":        "https://…",
      "submittedAt": "2026-09-27T10:58:55.948Z"
    }

  Content-Type при этом text/plain, а не application/json — из-за CORS,
  как объяснено в шаге 6. На разбор это не влияет: скрипт всё равно
  получает тело запроса и разбирает его как JSON.

  readData пробует три способа по очереди и берёт первый, где нашлось
  хоть одно имя или телефон:
    1. e.parameter — если запрос form-encoded, Apps Script разбирает
       его сам, это самый надёжный путь;
    2. JSON.parse тела — так шлёт сайт;
    3. тело как a=1&b=2 — запасной вариант.

  Имя поля телефона не важно: phone, tel, mobile, telephone и даже
  «Телефон» приводятся к колонке «Телефон» в любом регистре.

  Если не сработал ни один — в таблицу пишется причина, а не пустые
  поля. Поэтому та ситуация, когда в строке есть только дата, больше
  невозможна вслепую: причина всегда видна.


───────────────────────────────────────────────────────────────────────
  ЕСЛИ НУЖНО ТЕЛЕГРАМ-БОТ
───────────────────────────────────────────────────────────────────────

  Скрипт уже умеет слать заявку в чат. Достаточно заполнить
  TELEGRAM_TOKEN и TELEGRAM_CHAT в SETTINGS и сделать новое развёртывание.

  Прямо из браузера в Telegram отправлять нельзя: Bot API не
  поддерживает CORS, а токен пришлось бы держать в коде страницы.
  Так что бот работает через этот же скрипт — это серверная отправка.
